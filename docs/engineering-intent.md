# 校园活动管理系统 V1.0 工程意图

## 1. 建设目的

当前版本用于验证校园活动的发布、发现、报名和结果查看能否通过一个结构合理、基本可运行的软件形成完整业务闭环。系统解决分散通知和线下报名导致的信息入口不统一、教师难以掌握报名情况等问题。

## 2. 本轮范围

V1.0 完成以下内容：

- 用户注册、登录、退出和学生/教师角色访问控制；
- 教师创建、编辑、删除 `DRAFT` 活动并发布；
- 学生浏览 `PUBLISHED` 活动及详情并在规则允许时报名；
- 学生查看和取消自己的报名；
- 教师查看本人活动的报名人数、名单并关闭活动。

本轮不建设完整校园活动平台。管理员、审核、搜索、分类、推荐、评论、通知、签到、导出、报名审批、复杂前端和分布式基础设施均不在范围内。

## 3. 重要约束

- 技术栈固定为 Java 21、Spring Boot 4.1.1、Maven、Spring MVC、Thymeleaf、Spring Data JPA 和 MySQL 8.4。
- 使用 `HttpSession` 保存登录状态；BCrypt 仅通过 `spring-security-crypto` 使用，不引入完整 Spring Security 登录体系。
- Controller 负责请求和页面流程，Service 负责业务规则和权限检查，Repository 负责数据库访问。
- 教师资源操作必须在 Service 层验证创建者所有权。
- 报名重复检查必须同时具有 Service 主动判断和数据库 `(student_id, activity_id)` 联合唯一约束。
- 所有状态修改使用 POST；UI 只需可读、可填写、可操作。
- 数据库连接使用环境变量，不在仓库中保存密码、Token、私钥或真实个人隐私数据。
- 不得未经确认扩大 V1.0 范围；若需求、数据模型或设计必须变化，应先更新工程文档并说明原因。
- Git 和 GitHub 历史必须由真实阶段性提交形成，不事后伪造或重写。

## 4. 完成依据

当以下条件全部成立时，V1.0 达到预期目标：

- REQ-01 至 REQ-06 均已实现，并能从页面实际完成学生和教师核心流程；
- 关键业务规则能拒绝越权、重复报名、满员、截止和错误状态等非法操作；
- TEST-01 至 TEST-06 具有实际执行结果；
- Maven 测试通过，应用能够连接本地 MySQL 8.4 启动；
- 实现与需求和设计基本一致，不存在未经确认的范围扩展；
- GitHub 仓库中的阶段性历史能够反映文档、工程基线、功能和验证逐步形成；
- 仓库不存在真实密码或其他敏感信息。
